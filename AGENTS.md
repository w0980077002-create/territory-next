# TERRITORY 2.0 — правила для разработчиков и ИИ-агентов

Этот репозиторий — **только TERRITORY 2.0**. Не переносить сюда код, графику, учётные записи, данные игроков или миграции из TERRITORY 1.0. Не менять production Supabase.

## Источник истины

- Для игровых экранов: `docs/TERRITORY_2_0_CANON/SOURCE_OF_TRUTH_RU.md` и оригинальные утверждённые изображения. Главный эталон уже в `docs/reference/TERRITORY_2_0_APPROVED_2026-10-24.jpg`; остальные пять оригиналов пока не загружены в этот репозиторий. Кадры в `docs/video-frames/` — не их замена.
- Не придумывать расположение кнопок, цвета и механику вопреки эталонам. Яркий насыщенный мультяшный стиль викингов, не реализм и не старые мрачные персонажи.
- Пять нижних игровых кнопок, две сферы, сетка экипировки и расположение элементов защищены контрактом экрана.
- Игровой код: `src/v2/`, серверная инфраструктура V2: `server/`, `supabase/functions/territory-v2-api/`; тестовая схема БД — `territory_v2`. Любые реальные начисления/перенос из V1 запрещены.

## Рабочий цикл

1. Прочитать относящийся к задаче раздел канонического ТЗ. Не перечитывать весь архив документов для простой правки.
2. Сделать законченную игровую функцию или отдельный проверяемый визуальный результат. Использовать data-driven конфигурацию вместо хардкода игровых предметов и умений.
3. Проверить `npm run typecheck`, `npm run test:v2` и `npm run build`; для анимационного инструментария — `npm run art:workshop:check`.
4. Для изменений HUD сравнить кадр того же viewport с утверждённым эталоном. Для бойцов показать цикл движения покадрово и измерить устойчивость стоп, целостность суставов, положение оружия и попадание в цель. Неподвижное изображение, которое целиком качается/ездит, не считается анимацией бойца.
5. Не подменять проверку игрового процесса скриншотом. Первая играбельная петля и стабильность сохранения важнее бесконечной полировки декора.
6. Для видео боя и проверки анимаций использовать `npm run art:video:sheet -- <video> --range START:END:STEP --out .workshop/review.jpg`; для сравнения до/после — `npm run art:video:compare -- <before.mp4> <after.mp4> --out .workshop/compare.mp4`. Источник — MIT `studioigor/3d-animator-skill`.
7. Когда ИИ исправляет только кнопки или оформление, проверять diff через `npm run qa:ui-diff -- <branch> <base>`: неожиданное изменение игрового состояния, баланса, серверных операций и сохранений необходимо исследовать до слияния.
8. Декоративные рамки/картинки, динамический текст и данные держать отдельно. Проверять 320px/390px, длинные подписи и восстановление вкладок: идея из `studioigor/lighthouse-uikit`, код и чужие изображения не импортируются.
9. Для разработки или проверки экранов по изображениям применять локальный `.agents/skills/reference-uikit/SKILL.md` вместе с его `references/`. Этот навык установлен отдельно: визуал **только наш утверждённый яркий Viking**, а не демонстрационная морская тема автора. Проверять именно оригиналы из `docs/TERRITORY_2_0_CANON/SOURCE_OF_TRUTH_RU.md`.
10. Для анимированной 3D-модели использовать отдельный браузерный конвертер `tools/3d-to-2d/` (`npm run art:sprite-converter`, затем http://127.0.0.1:8765), с последующей проверкой 2D-кадров. Он не публикуется через GitHub Pages, не импортируется в React-код игры и не заменяет `ref2game` для нарисованных 2D-героев. `npm run qa:creative-addons` проверяет обе установки.

## Бесплатные инструменты Игоря

- MIT-набор `ref2game` доступен локально: `.agents/skills/ref2game/SKILL.md`. Его **WebGL-шаблон — только самостоятельная мастерская 2D-прототипов**. Никогда не вызывать `setup.sh` с корнем этого репозитория как `<project>` и не заменять им действующий React/Vite-клиент.
- Для новых анимированных героев/врагов: `npm run art:workshop:prepare -- <id> <hero|companion|enemy|boss>`; результат лежит в исключённой из Git папке `.workshop/v2-actors/`.
- Пошаговые инструкции и лицензии: `docs/TERRITORY_2_0_FREE_STUDIO_TOOLS_RU.md`.
- Полная проверка **26** репозиториев Игоря и лицензий: `docs/STUDIOIGOR_ALL_26_REPOS_AUDIT_20261025_RU.md`.
- Установлены отдельный конвертер 3D→2D и навык `reference-uikit` (без чужой игровой графики); использование, ссылки и ограничения: `docs/STUDIOIGOR_CREATIVE_ADDONS_20261025_RU.md`.
- Для новых героев, спутников, врагов и боссов использовать единый [промпт для 2D-ассетов](docs/TERRITORY_2_0_CHARACTER_ART_PROMPTS_RU.md): одиночный ключевой кадр, затем лист частей того же персонажа; исходный ковбойский пример не является нашим художественным ТЗ.
- Перед переносом прототипного арта в игру: сверить его с каноническим ТЗ, проверить прозрачность, отдельные части тела/амуниции, цикл idle/run/attack/hit и корректное направление взгляда. Только после этого интегрировать как оригинальный арт V2.

Не подключать чужие автопилоты, cron, платные сервисы или внешние ключи без отдельной необходимости. Готовую игру, доступы игроков и историю нельзя приносить в жертву скорости прототипирования.
