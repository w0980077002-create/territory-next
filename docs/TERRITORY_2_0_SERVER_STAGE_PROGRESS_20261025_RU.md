# TERRITORY 2.0 — серверная фиксация прохождения этапов (25.10.2026)

**Реализовано в main, без подключения к игрокам:** `server/staging/territory_v2_pve_stage_progress.sql` + `scripts/check-v2-pve-stage-progress.mjs`.

## Почему это важно
Демонстрационный переход на следующую волну на клиенте не может быть источником правды: игрок может повторить запрос, открыть две вкладки, подменить данные или нажать кнопку во время задержки. Теперь имеется отдельная серверная транзакция **только для первого подтверждённого прохождения** этапа, не зависящая от клиентских счётчиков.

## Контракт
1. Только `service_role`, `SECURITY INVOKER`, приватная схема `territory_v2`, RLS без политик для браузера. Не добавлять функцию в публичный Data API.
2. Вход: `battle_id` и `clear_operation_id`, **только с доверенного сервера**. Никаких переданных браузером `player_id`, `outcome`, `stage`, `score`, `XP`, `loot` или `currency`.
3. Проверяет существование серверного боя, подтверждённую победу `settled/victory`, подписанный серверным контуром receipt `pve.resolve`, совпадение SHA-256 боевого лога, текущую главу/волну персонажа.
4. Блокирует строку персонажа до проверки и изменения. Только один первый clear для `(player, chapter, wave)`, повтор `(battle_id, clear_operation_id)` возвращает **точно тот же результат** без второй записи и второго повышения.
5. Прогресс: `1-1 → 1-2 → ... → 1-20 → 2-1 → ... → 5-20`; финал `5-20` остаётся конечным. `highest_unlocked_chapter` и `revision` изменяются атомарно.
6. **Не начисляет** XP, монеты, алмазы, предметы, билеты, VIP, дроп и платежи. `xpGranted=false`, `awardsGranted=false`. Отдельный будущий баланс и серверная выдача ещё не утверждены.
7. Повтор старого боя, поражение, чужой receipt, повтор финала, устаревшая волна, несуществующий бой → отказ без побочных эффектов.
8. Запрещено применять SQL в TERRITORY 1.0. Не применять в существующую V2 staging без отдельного плана безопасного развёртывания; в этом пакете только GitHub и изолированный CI/PGlite.

## Тестирование
Новый тест исполняет реальную SQL-миграцию в памяти PostgreSQL/PGlite, дважды применяет миграцию, проверяет права, RLS, жизненный цикл побед/поражений, идемпотентность, смену глав, финал кампании, отсутствие выплат и блокировку `anon/authenticated`. Он включён в `npm run test:v2` и CI ветки main.
