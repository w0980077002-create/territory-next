# TERRITORY 2.0 — матрица внедрения механик по проверенным источникам

**Фиксация:** 24.10.2026. Этот документ конкретизирует [исследование источников](TERRITORY_2_0_REFERENCE_RESEARCH_20261024_RU.md).  
**Дизайн НЕ менять:** [утверждённое фото](reference/TERRITORY_2_0_APPROVED_2026-10-24.jpg). Старый проект и рабочий Supabase не трогать.

## Основной принцип разработки без догадок

- **Подтверждён сам факт механики** → можно реализовать базовый интерфейс, типы данных и тесты взаимодействия.
- **Не подтверждена конкретная формула, вероятность, цена, таймер, цена в магазине, разблокировка или состав награды** → не придумывать «как было у конкурентов». Значение `TBD`, никаких реальных операций с деньгами и валютой до отдельно разработанных и протестированных оригинальных правил TERRITORY.
- **Существование функции только в Китае/отдельном патче** → задокументировать источник и ветку версии; разработка возможна как часть **одобренного владельцем направления**, не объявлять глобальную функцию Lootborn.
- **Соцсети/обзоры** → свидетельство о практике игроков, а не достоверный полный механический контракт.
- **Зарегистрированный дизайн** всегда сильнее внешних картинок, которых владелец запретил использовать в дизайне TERRITORY.

## Этап D — эксплуатация и сохранность (обязательно для любого релиза)

1. Отдельный `territory-next` и отдельный `staging Supabase` + telegram initData проверять на сервере.
2. Game loop и лут через серверные receipts, атомарность, unique constraints, серверные конфиги, антидуп и rate limiting.
3. Сохранить резервные копии, прогресс, предметы, VIP, валюту и ID игроков при возможной будущей миграции **без произвольной ребалансировки старых аккаунтов**.
4. При баге блокировать *спорные награды/операции*, не выполнять автоматическую блокировку людей; окончательное решение об аккаунтах — у владельца.
5. Испытать слабые Android, iOS/Telegram WebView, длинные сессии, многократное открытие разделов, отсутствие лагов и зависаний кнопок. На COC такие баги явно документировались (COC-20).
6. Платные товары, реальные платежи, реклама, призы и любые признаки play-to-earn — **только отдельный одобренный проект с проверкой законности и доступности в регионах**. Сюда не включена обещанная ценность токенов.
7. Игроку не нужно бесконечно вручную подтверждать каждую вещь или покупать очередной камень для любого рядового удара: это требование качества TERRITORY, основанное на жалобах игроков, **не описание чужого кода**.
8. **Никогда не публиковать тестовые начисления**; до релиза все награды в UI помечены как демо и не пишут в production.

## Критерии готовности (не путать с «сделано»)

- [ ] Функциональные классы и их ротация сборок
- [ ] Пять видов умения и рунические модификаторы, уникальные способности
- [ ] Параметризуемые наборы/аффиксы/переработка, серверное хранение
- [ ] Роли спутников и аур, пробуждение, сохранение ID
- [ ] Непрерывные главы, боссы, кейсы сопротивлений
- [ ] Рейды, многоэтажные подземелья и сезонность
- [ ] PvP с рейтингами и защитой боевого расчёта
- [ ] Шахты, порт/корабли и досуг
- [ ] Соцмеханики/награды/промо/кланы
- [ ] Изолированная база staging и защита доходов и сохранений
- [ ] Визуальная приёмка **по фото владельца**, оптимизация на телефонах
- [ ] Проведены тесты, владелец отдельно разрешил релиз

**Запрет:** не считать ни одну галочку выполненной из-за одного лишь макета, скриншота или имитации боя. Требуется проверяемое приложение и тесты.
