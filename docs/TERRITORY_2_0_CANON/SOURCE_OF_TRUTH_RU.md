**Не доказано кадрами и не должно изобретаться:** содержимое меню из 4 клеток; содержимое еженедельной награды и Пути Героя; полные карточки предметов; подэкраны всех правых кнопок; точные эффекты 15 активных умений; действие двух боковых кнопок навыков; конкретный рецепт/шансы синтеза; название скрытой пятой категории камней; таблицы наград, таймеры/ресеты, PvP алгоритмы, полное содержание трёх приключений. На перечисленное могут существовать **дополнительные подтверждённые материалы** в предыдущем видео и исследованиях, но если материал не описывает конкретный параметр, он остаётся открытым, а не становится поводом дописать фантазию.

**Текущее ТЗ — ориентир реализации, а не отчёт о готовности.** Любая строка становится `ГОТОВО` только при наличии работающего кода, реального маршрута, корректного хранилища и прошедших тестов на реальных разрешениях. Наличие скриншота, мокапа, нарисованной кнопки или комментария в GitHub не равно завершённой механике.

## 11. Процесс разработки без подмен и недоделок

1. **Зафиксировать исходники:** шесть неизменных файлов и этот документ в одной папке; у каждого — неизменное имя и контрольная сумма. В репозитории сохранить ссылки на эту каноническую папку/снимки.
2. **Строить строго экран за экраном по назначению**, но не выдавать недоделанный экран за готовый: верстка → активные кнопки → навигация и возврат → состояние → серверные операции, где они нужны → тесты → сравнение с эталоном.
3. **Визуальная проверка:** для каждого из шести экранов создать скриншот текущей реализации, сравнить его с соответствующим исходником по рамкам/пропорциям/компоновке/шрифтам/цветам/подписям и исправить отклонения до утверждения. Не включать системный Android/Telegram chrome в app-макет.
4. **Функциональная проверка:** отдельный журнал результатов для каждой строки кликовой матрицы, без выдуманных зелёных галочек. При нарушении любого обязательного пункта — «не принято».
5. **Изменения:** если референсы расходятся между собой, приоритет исходной конкретной страницы; если правило действительно несовместимо — не исправлять самостоятельно, а зафиксировать конфликт и получить новое решение владельца.
6. **Публикация:** только после тестирования; не трогать первую TERRITORY и её БД. Все финансовые/наградные изменения требуют отдельных серверных тестов, защит и явного разрешения.
