# TERRITORY 2.0 — производство и подключение движений

**Дата:** 25.10.2026 · **Источник идеи:** переданный владельцем `movement.txt` (image-to-video, бег на месте).

Это техническое дополнение к [единому стандарту персонажей](TERRITORY_2_0_CHARACTER_ART_PROMPTS_RU.md), **не замена** [утверждённому визуальному эталону](TERRITORY_2_0_CANON/SOURCE_OF_TRUTH_RU.md). В оригинальном файле — ковбой, револьвер, хромакей и озвученное видео. Мы переносим только удачные правила непрерывного движения, не копируем ковбоя, звук или Western-стиль.

## Производственная последовательность

1. `npm run art:workshop:prepare -- <actor-id> <hero|companion|enemy|boss>` — отдельные `BRIEF.md` и `MOTION_PROMPTS.md` в исключённой из Git `.workshop/v2-actors/<actor-id>/`. При повторном запуске существующие файлы сохраняются.
2. Нарисовать и **принять** один оригинальный прозрачный ключевой кадр по утверждённому Viking-стилю. После него — части того же персонажа для рига; зафиксировать ID, цветовую схему, масштаб, направление и точку контакта стоп.
3. По шаблону из `MOTION_PROMPTS.md` производить **отдельный клип** для каждого состояния. Использовать исходный принятый кадр как обязательный reference. Отсутствие реального подтверждённого референса нельзя компенсировать придуманными деталями.
4. Из ролика извлечь кадры без размытия и интерполяции, убрать фон с реальным alpha-каналом, вручную проверить покадровый лист. Ролик с зелёным фоном — **промежуточный материал**, никогда не итоговый игровой атлас. Склеивать в горизонтальный sheet: N одинаковых кадров `W×H`, общий размер `(N×W)×H`.
5. Проверить движение ног, суставов, кистей и оружия, стабильность точки опоры, отсутствие мерцания, дрейфа камеры, масштаба и дополнительных деталей. Для `run` и `idle` первый и последний фазы должны бесшовно стыковаться. Видео и лист кадров проверять через `npm run art:video:sheet` и мастерскую ref2game; неподвижная картинка, которая качается целиком, **не проходит**.
6. Только после приёмки положить оптимизированный WebP/PNG-атлас с прозрачностью в `public-v2/art/motion/<actor-id>/<state>.webp`, а параметры — в `src/v2/animation/motionManifest.json`. Затем `npm run test:motion`, `npm run art:workshop:check`, `npm run typecheck`, `npm run test:v2`, `npm run build`.

## Клипы

| Состояние | Назначение | Важные требования |
|---|---|---|
| `idle` | ожидание | спокойное дыхание, неподвижные опорные стопы, цикл |
| `run` | бег/сближение | попеременные шаги и противофазные руки; торс немного подаётся вперёд, корень остаётся на месте; цикл |
| `attack` | обычная атака | замах → контакт → восстановление; оружие закреплено в руке |
| `skill` | активный навык | отдельный жест/оружие, эффект магии рисует движок |
| `hit` | получение урона | реакция корпуса и головы без исчезновения частей |
| `block` | блок | предмет защиты закрывает линию удара |
| `dodge` | уклонение | корпус и стопы работают согласованно, нет телепорта |
| `death` | гибель | конечная поза, без бесконечного цикла |
| `victory` | победа | отдельная короткая последовательность |

Для четвероногих и летающих спутников вместо человеческого шага создавать собственную анатомически корректную локомоцию. Герой/спутник смотрят вправо, враг/босс влево. **Не отражать картинку программно:** щиты, топоры и асимметричные элементы закреплены в правильной руке.

## Контракт воспроизведения

`motionManifest.json` содержит реальные и прошедшие приёмку атласы. Пример одного клипа, **не вставлять до появления проверенного файла**:

```json
"run": {
  "src": "art/motion/berserker/run.webp",
  "frames": 12,
  "fps": 12,
  "width": 300,
  "height": 360,
  "loop": true
}
```

- Кадры одинакового размера, единая позиция ступней и размер фигуры; фон действительно прозрачный. Не масштабировать отдельные позы.
- `fps` — визуальная скорость кадров, `width`/`height` — размер **одного** кадра. Ускорение ×2 влияет только на визуальное воспроизведение. Числа урона и наград не зависят от анимации.
- `hitFrame` для `attack`/`skill` при необходимости указывает кадр столкновения (индекс с нуля). Подтверждённое событие урона приходит из боевой логики; визуал не начисляет урон самостоятельно.
- При отсутствии принятого клипа игра показывает существующий оригинальный статичный SVG; не пытается скачать несуществующий файл и не имитирует анимацию движением всей картинки.
- Аудио хранить отдельными короткими файлами, синхронизировать с игровым событием / кадром контакта. Никакой музыки и случайных звуков, запечённых в спрайты.
- Непрерывный `run` не перезапускается на каждом игровом тике; разовый `attack`/`hit` запускается заново по номеру события.

## Границы

Никаких изменений экономики, авторизации, Supabase, V1 или утверждённых зон HUD. Промежуточные AI-ролики/непроверенные листы остаются в `.workshop/`, не попадают в GitHub Pages. В репозитории пока **нет принятого покадрового исходника**, поэтому одних метаданных и промптов недостаточно, чтобы честно назвать каждого героя анимированным. Каждую роль подключать по мере готовности качественных оригинальных атласов.
