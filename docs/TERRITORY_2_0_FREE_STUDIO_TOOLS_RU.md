## Что реально стало доступно в проекте

1. Локальный оригинальный `ref2game` со скриптами `rigcut.py`, `partrig.py`, `jointr.py`, `qa.mjs`, `compare.py` и движком для отдельной мастерской. Авторская лицензия MIT сохранена рядом.
2. Единые правила для ИИ в корневом `AGENTS.md`: неприкосновенный эталон, автономное создание, 2D-анимация с суставами, обязательные проверки. Это избавляет от повторных длинных объяснений при новых задачах.
3. Команда подготовки нового бойца с готовым техзаданием, набором обязательных слоёв, состояний движения и контрольными критериями:

   ```bash
   npm run art:workshop:prepare -- berserker hero
   npm run art:workshop:prepare -- frost-boss boss
   ```

   Черновики создаются в `.workshop/v2-actors/`, **не попадают на GitHub Pages и не трогают код игры**. Если такой персонаж уже существует, исходный бриф не перезаписывается.

4. `npm run art:workshop:check` проверяет наличие инструментов, лицензию и контрольные точки риг-проверок. GitHub Actions также отдельно проверяет JavaScript-синтаксис браузерных скриптов после `test:v2`.

## Вторая проверка всех 26 репозиториев автора

Полный список с назначением, совместимостью, точной причиной включения/отказа и лицензиями хранится в [аудите](STUDIOIGOR_ALL_26_REPOS_AUDIT_20261025_RU.md). После этой проверки добавлены ещё два переносимых инструмента:

- **Покадровый разбор видео** из MIT-навыка [3d-animator-skill](https://github.com/studioigor/3d-animator-skill): без Blender и 3D можно взять уже существующий MP4 боя, сделать лист кадров или сравнить два видео. Команды `npm run art:video:sheet -- ...` и `npm run art:video:compare -- ...`. Требуются бесплатные `ffmpeg` и Pillow, которые не добавлены к игровому бандлу.
- **Детектор опасных UI-правок** из MIT-процесса [gamestudio](https://github.com/studioigor/gamestudio): `npm run qa:ui-diff -- <ветка> <основная-ветка>`. Выводит список TS/TSX/SQL файлов вне CSS-зоны, которые нужно читать глазами, если задача была только изменить внешний вид.

Ещё две полезные идеи остаются **внешними**: [3D → 2D sprite sheet](https://studioigor.github.io/3d-to-2d/) для случая появления собственного анимированного GLB и [reference-uikit](https://github.com/studioigor/lighthouse-uikit/tree/main/skills/reference-uikit) как методика создания UI по картинкам. У этих репозиториев на дату аудита не было отдельного файла `LICENSE`; чужие файлы и художественные ресурсы не копировались.

## Как оживить персонажа

1. Подготовить бриф и утверждённый визуальный референс; не использовать внешние картинки как готовые игровые ассеты.
2. Сгенерировать уникальное цельное изображение бойца **с обеими руками, обеими ногами и амуницией**, затем отдельный лист деталей на прозрачном фоне. Чётко разделить плечо/предплечье/кисть, бедро/голень/стопу и крепление оружия.
3. В **изолированной** мастерской создать WebGL-прототип, например (зависимости установятся при первом запуске `setup.sh` только в папке навыка):

   ```bash
   bash .agents/skills/ref2game/scripts/setup.sh .workshop/v2-actors/berserker/prototype --ref docs/reference/TERRITORY_2_0_APPROVED_2026-10-24.jpg --genre side
   ```

   Нельзя запускать `setup.sh .` — этот шаблон живёт отдельно от React/Vite. `ref2game` использует Pillow/NumPy/SciPy и Playwright/Chromium; они **не установлены автоматически** при добавлении исходников в репозиторий. Иных платных API-ключей не нужно.
4. Собрать риг и анимации; в папке **прототипа** запустить `node <абсолютный-путь-к-навыку>/scripts/qa.mjs`. Это отдельный тест WebGL-прототипа, а не готовая проверка React-анимации. Проверить покадровые листы: руки не отрываются, меч не плавает, ноги не скользят, удар попадает в точку контакта.
5. Только после прохождения проверки интегрировать **оригинальные ассеты** и совместимую с текущим движком анимацию в `src/v2/`, проверить поведение на Android и iPhone.

## Автоматический цикл качества вместо десятков случайных правок

Для каждого важного экрана или действия: зафиксировать эталон и viewport → собрать работающую функцию → выполнить `typecheck`/`test:v2`/`build` → снять кадры того же размера и проверить игровой цикл → записать **одно главное** отличие от эталона → устранить его → повторить. Исходный канонический скриншот никогда не заменять снимком нашего промежуточного результата.

Приоритет первого использования мастерской: **правдоподобное движение героя и противников**. Следующий — быстрый выпуск разных наборов врагов/спутников и визуальные сравнения экранов. Никаких изменений реальной экономики или Supabase этот пакет не делает.
