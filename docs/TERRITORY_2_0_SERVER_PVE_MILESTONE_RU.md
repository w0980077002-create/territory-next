# TERRITORY 2.0 — следующая реализация ТЗ: серверный PvE

**Дата:** 24.10.2026. **Репозиторий:** territory-next. **Окружение:** отдельная Supabase-staging `ksikzkrvuuhermhnbycn`, не production TERRITORY 1.0. **Фото-эталон:** `docs/reference/TERRITORY_2_0_APPROVED_2026-10-24.jpg` — не изменено. Фон и художественные файлы не затронуты.

## Соответствие ТЗ

- **GMP-02 / SCR-01 / SCR-09 / E2E-010–019 / SEC-02:** состояние серверного PvE, конечный результат и единичная запись результата.
- **Server combat:** `server/combat/resolvePve.ts` — отдельный от Vite frontend модуль детерминированного расчёта с вводимым версионированным набором правил `PveRuleset`. Содержит валидацию, конечный предел хода, удары/криты/уклонения/преобразование защиты, единственную фазу босса, развёрнутый таймлайн. Коэффициенты и seed передаются **исключительно проверенным сервером**, не UI. **Исходные тайные формулы Lootborn / COC неизвестны** — здесь не копия формул, а безопасная инженерная основа с параметрами из явного набора правил.
- **Staging migration:** `server/staging/territory_v2_pve_protocol.sql` — закрытый реестр battle sessions и snapshots, разрешение на старт только при владении персонажем и наличии разрешённой серверной версии правил, один незавершённый бой на аккаунт, повторный старт по тому же ID без создания дубликатов, единичная запись результата с receipt и блокировкой других результатов при повторе. `SECURITY INVOKER` / `service_role` only, нет прямых пользовательских привилегий, обе новые таблицы с RLS.
- **Tests:** `scripts/check-v2-server-pve.mjs` (победа/поражение/таймаут/фаза босса/детерминизм/недопустимые входные данные), `scripts/check-v2-pve-protocol.mjs` (на настоящей модели PostgreSQL/PGlite: права, чужие аккаунты, гонки, повторные награды, ledger=0, последовательные попытки), `scripts/check-v2-project-isolation.mjs` (новые функции недоступны public/anon/authenticated).

## Строгая граница работоспособности

- **Никаких реальных наград**: settlement записывает результат, но `awardsGranted=false`, НЕ меняет кошелёк, предметы, XP или chapter_progress. Это сознательно закрытая стадия до конфигурации оригинального баланса и серверной выдачи.
- **Нет живого API для игроков**: браузерная демоверсия по-прежнему локальная, серверные функции не вызываются клиентом, отдельный server-to-server handler и отдельный Telegram-бот всё ещё отсутствуют. Клиент ни при каких обстоятельствах не должен передавать `outcome`, `trace hash`, `player ID`, `seed` или статы в privileged SQL функции — они поступят от доверенного бэкенда после проверки Telegram HMAC и player authorization.
- **Значение слова «готово»**: это завершённый проверяемый кирпич для будущего серверного боя, не полная живая PvE-игра. Нельзя включать реальные награды до безопасного backend API и утверждения балансных таблиц.
- **Безопасность 1.0:** никакие изменения `territory-game-builde` или `wmyrdpbwlkzsktnhookx` не допускаются.
