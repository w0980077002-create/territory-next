# TERRITORY 2.0 — инженерный этап 27.10.2026: серверная история кампании (только чтение)

**Ветка:** `main` репозитория `w0980077002-create/territory-next`. Разработка отдельной V2 без любых изменений первой игры, её Supabase, бота, VIP, валют и игроков.

## Реализовано
- `server/api/campaignSnapshot.ts`: один фиксированный параметризованный SQL-запрос по **подписанному Telegram ID** возвращает текущую главу/волну, версию персонажа, число **серверно подтверждённых** прохождений, признак завершения 5-20 и последние десять результатов с датами UTC. Ограничение 5×20, строгая проекция полей и валидация ответов; не отдаёт внутренние playerId/characterId, кошельки, токены и сырые battle receipts.
- `server/api/telegramGateway.ts`: новый `POST /campaign` с тем же Origin/HMAC/JSON-gate, что и `/profile`. Бюджет запросов **общий** с `/profile`, чтобы не получить обход rate-limit. Уточнено строгое совпадение пути: поддельные окончания URL больше не маршрутизируются.
- `supabase/functions/territory-v2-api/index.ts`: подключён новый read-only обработчик к **отдельному staging** проекту; по умолчанию шлюз выключен. Не запускает бой и не выдаёт наград.
- `scripts/check-v2-campaign-gateway.mjs`: проверка запрета forged initData, чужого Origin, подмены playerId/этапа, отсутствующего/выключенного шлюза и лимита.
- `scripts/check-v2-campaign-snapshot.mjs`: настоящая SQL-интеграция на локальном PGlite, 2 разных игрока, 13 этапов, 10 последних, RLS/права, запрет SQL-инъекций и нулевые записи в экономику.
- Тесты включены в `npm run test:v2` и `npm run test:campaign-gateway`.

## Что сознательно НЕ делали
- **Не разворачивали** новый код на живом Edge, не включали gateway и не подключали клиент к серверу. До отдельного подтверждения V2-бота, защищённого серверного исполнения боя и полноценного staging-flow остаётся только исходный код.
- **Не начисляли** опыт, монеты, алмазы, предметы или реальные награды; `/campaign` исключительно читает уже записанные сервером подтверждения.
- Не трогали фон и шесть утверждённых эталонов, не включали платежи и не публиковали релиз игрокам.

## Следующий этап
Закончить серверный оркестратор боя: защищённый старт с фиксированным snapshot, секретным seed и версионированными правилами; детерминированный resolve; единичный receipt и clear. Только после этого можно соединять клиентскую кампанию с реальными серверными результатами. До этого клиент остаётся локальной демонстрацией.
