## Что ещё НЕ сделано

- Нет отдельного созданного Supabase-проекта для 2.0. Проверены доступные проекты: присутствуют только старые `territory-game-builde` и `bolt-native-database-71669285` — оба не затронуты. Перед реальным staging нужны выбор организации и подтверждение возможной стоимости нового проекта.
- Нет реального серверного Telegram initData-логина / wallets / loot / battles / PvP / persistent presets. Используются локальные демонстрационные состояния; любой отображаемый баланс в preview — выдуманные **значения мок-демо, не реальные награды**.
- На главном экране пока остались временные ассеты первоначального технического пакета. Они не считаются визуальным эталоном. Их нужно заменить оригинальными художественными ассетами, создаваемыми **исключительно** по [утверждённому фото](reference/TERRITORY_2_0_APPROVED_2026-10-24.jpg). Pixel-perfect приёмка владельца **не пройдена**.
- Некоторые боковые разделы пока информационные заглушки, а не игровые функции; пометки `done` для всей 34-экранной карты нет.
- Без отдельной staging-системы начислений ничего не публиковать игрокам или связывать со старым Telegram-ботом.

## Пройденные проверки

- `npm run typecheck` — TypeScript.
- `npm run test:v2` — в том числе неизменность эталона, кампании, пресетов, 53↔ТЗ↔55 E2E трассировка, игровая симуляция, экономическая изоляция и локальный PostgreSQL.
- `npm run build` — сборка с несуществующим offline endpoint.
- [GitHub Actions — успешно проверенный пакет с серверной SQL-заготовкой](https://github.com/w0980077002-create/territory-next/actions/runs/40073626417).
