## B. Сценарии пользовательского уровня — Given/When/Then

### Вход, профиль, экран (E2E-001…009)

1. **E2E-001 — новый пользователь:** GIVEN подлинное `initData` от нового telegram ID, WHEN входит, THEN один созданный `players`, один `characters`, виден tutorial, секреты не передаются в JS бандле.
2. **E2E-002 — повторный вход:** GIVEN существующий ID, WHEN вход через другой Telegram WebView, THEN тот же персонаж/VIP/предметы/баланс, не новый аккаунт.
3. **E2E-003 — spoof:** GIVEN произвольно подменённое `user.id` в `initDataUnsafe`, WHEN API вызван, THEN `401`, состояния не изменились.
4. **E2E-004 — срок действия:** GIVEN истёкшее `auth_date`, WHEN вход, THEN однозначный отказ/повтор handshake; никакая заглушка nickname не становится ID.
5. **E2E-005 — портрет:** WHEN тап на аватар, THEN экран героя с сохранённым контекстом, кнопки back/close возвращают к бою.
6. **E2E-006 — HUD:** GIVEN новая server wallet revision, WHEN клиент получает обновление, THEN значения валют и силы обновляются без смешения красных и синих алмазов.
7. **E2E-007 — скриншот:** GIVEN 864×1536 эталон, WHEN рендер desktop/mobile эталонной сцены, THEN расположение панелей/иконок/спутников/сфер/экипировки соответствует фото.
8. **E2E-008 — список кнопок:** WHEN последовательно нажаты все видимые shortcut/gear/bottom-action, THEN каждый открывает соответствующий раздел/действие либо видимый `locked` с обоснованием, без мёртвых нажатий.
9. **E2E-009 — узкий телефон:** WHEN 320/360/375/390/430 px, THEN нет горизонтального переполнения, сферы видимы, тап-зоны доступны, Telegram safe area не закрывает нижнюю панель.

### Автобой, главы, награды (E2E-010…019)

10. **E2E-010 — победа:** GIVEN stage доступен, WHEN серверная встреча победила, THEN ровно одна запись итога, одна награда, следующий этап, правильные анимации.
11. **E2E-011 — поражение:** GIVEN проигрыш, WHEN encounter settled, THEN не выдавать награду победителя; герою объяснить путь усиления.
12. **E2E-012 — двойной settle:** GIVEN одинаковый battleId/operation key, WHEN два одновременных завершения, THEN один ledger receipt, второй возвращает первый результат.
13. **E2E-013 — подделанный урон:** GIVEN клиент отправил `damage=99999999` либо `win=true`, THEN сервер игнорирует недоверенные поля; HP и outcome неизменны.
14. **E2E-014 — ×2:** GIVEN одинаковый бой и ruleset, WHEN пользователь включил скорость, THEN число серверных наград не удвоилось только от анимации.
15. **E2E-015 — offline/disconnect:** GIVEN вылет/перезапуск Telegram во время боя, WHEN восстановление, THEN тот же незавершённый server battle либо явно документированное серверное истечение, без нового дропа.
16. **E2E-016 — босс:** GIVEN запущен режим босса, WHEN проходит фаза, THEN уникальные эффекты/анимации и корректный результат по версии правил.
17. **E2E-017 — закрытый этап:** GIVEN user не выполнил prerequisite, WHEN попытка старта следующего, THEN `LOCKED_STAGE`, без списания камня.
18. **E2E-018 — другие вкладки:** GIVEN активный бой, WHEN открыть склад и вернуться, THEN состояние сохраняется и не появится второй активный бой.
19. **E2E-019 — незавершённый offline:** GIVEN нет подтверждённого online/offline ruleset, WHEN время устройства переведено на месяцы, THEN никакого добавленного XP/предметов.

### Билды, навыки, руны, предметы (E2E-020…030)

20. **E2E-020 — классы:** GIVEN 3 доступных класса/различные допустимые виды действий, WHEN сменён класс, THEN валидатор пересчитывает ограничения; стоимость смены из `TBD` не подставлена.
21. **E2E-021 — навыки:** GIVEN слоты 5 групп, WHEN игрок меняет умение, THEN видны категория, описание эффекта, кулдаун из правил; недоступное умение нельзя использовать.
22. **E2E-022 — руна:** GIVEN rune несовместима с skill, WHEN установка, THEN в UI объяснение и серверный отказ, без расхода.
23. **E2E-023 — пресет:** GIVEN два loadout, WHEN быстро переключить во время нагрузки/встречи, THEN эффект атомарно только когда разрешено правилами; два одинаковых itemInstance не активны одновременно.
24. **E2E-024 — экипировка:** WHEN тап на вещь в нижней панели, THEN непосредственно экран выбранного слота/предмета, сравнение характеристик.
25. **E2E-025 — эквивалентный предмет:** GIVEN заменяется оружие, WHEN equip, THEN меняются статы и set count, старое возвращается в склад.
26. **E2E-026 — незаконный слот:** GIVEN item чужой/неправильного типа/заблокирован, WHEN equip, THEN сервер запрещает и оставляет старую экипировку.
27. **E2E-027 — любимая вещь:** GIVEN locked/favorite/equipped, WHEN массовый salvage, THEN эта вещь цела, чек/ledger не содержит её списания.
28. **E2E-028 — перековка:** GIVEN confirmed ruleset+materials, WHEN улучшение, THEN ровно одно списание/новые свойства/журнал; при отсутствии материалов всё откатывается.
29. **E2E-029 — набор:** GIVEN два экземпляра одного сета надеты, WHEN снять один, THEN количество набора и эффект соответствуют серверному правилу, а не client toggle.
30. **E2E-030 — спутники:** GIVEN один main и support, WHEN main пытается стать одновременно support, THEN валидация отказывает без дубля аур.

### Испытания, PvP и социальные (E2E-031…042)

31. **E2E-031 — dungeon:** GIVEN закончился дневной лимит, WHEN старт, THEN понятная причина запрета, нельзя получить повторный loot.
32. **E2E-032 — фазовый босс:** GIVEN следующая фаза, WHEN HP порог достигнут, THEN эффект запускается ровно по ruleset и визуально предупреждается.
33. **E2E-033 — PvP:** GIVEN игрок A и B, WHEN матч, THEN уникальные player IDs и валидные snapshot-сборки.
34. **E2E-034 — PvP чат:** GIVEN матч жив, WHEN игрок отправил сообщение, THEN сразу видит чат, экипировку и компактные сворачиваемые эликсиры.
35. **E2E-035 — чат после боя:** GIVEN бой завершён, WHEN в течение 30 минут, THEN чат доступен; позже — закрывается серверной политикой.
36. **E2E-036 — рейтинг:** GIVEN два завершения матча с одним receipt, THEN очки начисляются единожды; недельный snapshot не удаляет постоянные ресурсы.
37. **E2E-037 — реферал:** GIVEN invitee выполнил порог, WHEN claim, THEN награда один раз; self-referral запрещён.
38. **E2E-038 — промокод:** GIVEN код истёк или использован, WHEN redemption, THEN отказ без награды, понятная причина.
39. **E2E-039 — письмо:** GIVEN письмо с 3 разными призами, WHEN `claim` 3 раза параллельно, THEN все 3 позиции начислены однократно в одной операции.
40. **E2E-040 — плановое письмо:** GIVEN указан scheduledAt, WHEN серверный scheduler сбоит и перезапускается, THEN одна доставка каждому адресату и журнал доставки.
41. **E2E-041 — клан:** GIVEN player покидает клан, WHEN распределяют награду, THEN правило eligibility/period из опубликованной версии, без ручной подмены.
42. **E2E-042 — модерация:** GIVEN flagged suspicious action, WHEN античит сработал, THEN уведомление владельцу, но не автоматический бан.

### Ресурсы/корабли/временный контент/монетизация (E2E-043…055)

43. **E2E-043 — добыча:** GIVEN одна активная 4-часовая, WHEN пытаются запустить вторую, THEN отказ; 4 часа на сервере, не на телефоне.
45. **E2E-045 — возврат рейса:** GIVEN корабль вернулся, WHEN 3 повторных claim, THEN один наградный receipt.
48. **E2E-048 — временный рюкзак:** GIVEN эвакуационная мини-игра, WHEN проигрыш, THEN потеря, если предусмотрена правилами, только внутри temp inventory, а обычный склад цел.
49. **E2E-049 — выбор из трёх:** GIVEN временное повышение навыка, WHEN выбран один, THEN выбор подтверждён, остальные два не применены.
50. **E2E-050 — бонус рекламы:** GIVEN поддельный `ad watched`, WHEN claim, THEN отказ, а настоящий network receipt уникален.
51. **E2E-051 — платёж:** GIVEN повторённый webhook, WHEN settlement, THEN одна покупка/начисление, подписанный источник.
52. **E2E-052 — изменение времени:** GIVEN пользователь переводит телефон/меняет часовой пояс, WHEN обновляется дневной лимит, THEN серверный periodKey и правила, без лишних призов.
53. **E2E-053 — миграция:** GIVEN снимок legacy accounts, WHEN dry-run, THEN UID/VIP/wallet/equipped/companions совпадают по инвариантам; без доступа к production.
54. **E2E-054 — база изоляция:** GIVEN билд V2, WHEN network requests, THEN никакого обращения к production Supabase или старому Telegram-боту.
55. **E2E-055 — отказ начислений:** GIVEN открытый preview, WHEN пользователь выиграл 1000 боёв, THEN серверная база, реальные аккаунты и реальные остатки не меняются.

## C. Обязательные состояния КАЖДОГО экрана

Для каждого `SCR-01…34` проверить в отдельной матрице:
- `not-loaded → loading → ready / empty / locked / error / offline`;
- `pressed → pending → confirmed / rejected / retryable-error` для изменяющих кнопок;
- открыть, прокрутить, вернуть назад, закрыть, сменить вкладку, восстановить фокус;
- недостаточно валюты / недоступная фича / ещё не открыт уровень / превышен лимит / предмет уже изменён / нет сети / отказ сессии;
- язык, размер шрифта, пробелы, safe areas, экранная клавиатура и touch behavior;
- `backend unavailable`: никакого обещания реальной выдачи или проигрыша;
- реалистичная синтетическая нагрузка на списки склада/вещей без выпадения кадров.

**Правило:** если не определены источник данных, UI-поведение, проверка прав и отрицательный кейс — экран считается `not-ready`.

## F. Производительность, UX, медиаконтент

- **NFR-01:** проверить устройства реальными профилями Android/Telegram и iPhone/Telegram, высоты safe area, сворачивание клавиатуры, многократные переходы по разделам.
- **NFR-02:** замерить `time-to-first-visible-UI`, `time-to-interactive`, отклик каждой вкладки, FPS и память на слабом телефоне; **измеренные целевые значения** — в отдельном performance budget, не наугад.
- **NFR-03:** тест включения/выключения звука, движения, вспышек, вибрации. Контраст текста поверх пейзажа, корректные `aria` и видимый статус.
- **NFR-04:** изолированный staging, секреты и токены отсутствуют в клиентском JS; SSR/Edge key safety и RLS.
- **NFR-05:** матрица арта `4 героя (2/2), 5 обычных ботов, 10 боссов, 5 спутников + взрослая боевая корова`, каждый idle/attack/hit/block/dodge/death там, где применимо, фон отдельных биомов и отдельная арена. Художественная приёмка только по эталону.
- **NFR-06:** ошибки сети, reconnect, миграция, резервное копирование, повтор запроса — без дюпа.
- **NFR-07:** сравнение миграционных снимков по `telegram_id, VIP, wallets, items, companions, quests, equipped`; rollback сценарий проверяется только на staging.
- **NFR-08:** нагрузка на backend по receipt/wallet/inventory, доказуемая устойчивость к одновременным обращениям. Нельзя считать `mock` тестом защищённой экономики.
