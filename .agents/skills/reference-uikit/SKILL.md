# UIKit по референсам

Результат — действующий интерфейс в стиле предоставленных изображений и переносимые компоненты. Для самостоятельного UIKit главная страница прежде всего показывает сами окна из референсов. Для интеграции в существующий проект используй его средства разработки; отдельные сцена, каталог, пример и архив создаются, когда входят в запрошенный результат.

## Приоритеты

1. **Визуальная верность.** Сохраняй композицию, пропорции, художественный стиль, формы, цвета, шрифтовой характер и исходные подписи. «Точь-в-точь» означает воспроизведение конкретных деталей, а не новую тему на похожую палитру.
2. **Настоящие компоненты.** Заголовки, числа, редкость, описания и подписи кнопок — живой текст. Панель растёт по содержимому; рамка и кнопка сохраняют характер при изменении ширины.
3. **Пригодность для игры.** Состояния, управление с клавиатуры, понятные события, независимость от страницы демонстрации.
4. **Локальная выдача.** По умолчанию запускай превью локально. Публикация не входит в этот workflow без запроса пользователя. Указанный движок, фреймворк и уже существующий проект имеют приоритет над примерной структурой ниже.

Не переноси в новый проект морскую тему, имена файлов, шрифты или размеры из прошлой задачи: образец для каждой новой работы — её собственные референсы.

## 1. Разобрать изображения

- Открой каждый референс, узнай его исходные размеры, изучи существующий проект и применимые инструкции.
- Зафиксируй короткую карту: окна, повторяемые элементы, видимые состояния, размеры крупных областей, шрифтовые признаки, отдельные иллюстрации. Достаточно заметок или компактной таблицы; не создавай длинный аудит вместо реализации.
- Раздели **содержимое**, **поведение**, **оформление**. Например: текст заголовка / закрытие окна / акварельный мазок под заголовком — три независимые части.
- Отдельно рассмотри изгибы и толщину рамки, неровные края, концы ленты, блики, нижнюю кромку кнопок, обводку букв, иконки, облака и декоративные пятна. Именно эти детали часто определяют сходство.
- Сначала сохраняй язык и подписи референса, чтобы честно сравнить результат. Локализацию и дополнительные состояния покажи отдельно, если они нужны.

Если изображения доступны и стек понятен, начинай работу. Спрашивай только о данных, без которых нельзя продолжить; не требуй согласования обычных обратимых решений.

## 2. Выбрать способ воспроизведения

| Элемент | Предпочтительный способ |
| --- | --- |
| Текст, счётчик, метка, индикатор | HTML/нативные элементы и CSS |
| Простая форма, обводка, служебная иконка | CSS или SVG в стиле референса |
| Рисованный предмет, портрет, фон | Самостоятельный растровый ассет |
| Акварельный заголовок, резная/сложная рамка | Отдельная подложка + 3-slice/9-slice либо убедительная векторная форма |
| Повторяющиеся текстура и пигмент | Маленькая текстура/слой, отделённый от геометрии и текста |

Для рисованных подложек и отделения иллюстраций читай [paint-and-assets.md](references/paint-and-assets.md). Если нужна генерация или художественное редактирование, используй доступный `imagegen` и его актуальный skill; по умолчанию встроенный инструмент. Не подменяй отсутствующий инструмент тихим переходом к платному API.

**Недопустимый результат:** готовая карточка или окно вырезаны из скриншота, растянуты как картинка, поверх положены текст и кликабельные области. Допустимо использовать исходные пиксели отдельного предмета или чистую рамку без надписей и управляемых состояний. CSS-фон не делает целый скриншот компонентом.

## 3. Сначала проверить характер, затем собирать все окна

Собери один показательный фрагмент: заголовок с подложкой, рамка, кнопка и строка/карточка. Покажи его в браузере рядом с соответствующим фрагментом оригинала при близком масштабе.

Исправь главные расхождения до тиражирования компонентов. Например, аккуратная синяя плашка не заменяет широкий акварельный мазок; толстый геометрический шрифт не заменяет мягкий рисованный. Не трать основное время на сайдбар, hero-блок и маркетинговую оболочку, пока сами окна не похожи на референсы.

Если используешь агентов, полезно разделить независимую работу: ассеты, базовые компоненты, проверка интеграции. Согласуй имена и контракт, назначь разные файлы. Визуальную сборку должен согласовать один ответственный агент.

## 4. Сделать библиотеку и превью

Для нового проекта без заданного стека подходит HTML + CSS + ES modules без обязательного фреймворка. Например:

```text
index.html              превью окон по референсам
preview.js              управление демонстрацией
kit/                    переносимые стили, компоненты, поведение
assets/                 только необходимые графика, шрифты и лицензии
examples/               маленький независимый пример, если он полезен
README.md               запуск, импорт, события, ограничения
```

- Несколько исходных экранов показывай отдельными сценами/вкладками. Панель управления превью не должна перекрывать игровые кнопки.
- CSS библиотеки ограничивай собственным префиксом/корневым классом; не меняй глобальные `body`, `button`, `*` чужой игры. Стиль демонстрационной страницы держи отдельно.
- Используй flex/grid, `min-width: 0`, переносы строк, `overflow-wrap`, относительные размеры и при необходимости container queries. Не масштабируй весь интерфейс через `transform: scale()` в качестве единственного способа адаптации.
- Размеры арт-областей могут быть фиксированными или иметь aspect ratio; высота контейнера с текстом должна следовать содержимому. Декор не перехватывает указатель.
- Все видимые действия работают согласно подписи: закрыть конкретное окно, переключить вкладку, выбрать предмет, показать допустимое состояние. Заблокированная награда имеет настоящий `disabled`, статусная метка не притворяется кнопкой.
- Свяжи `aria-controls`, подписи и фокус; поддержи клавиатуру для вкладок и reduced motion. Явно различай обычную панель и модальный диалог: модальность требует начального фокуса, его удержания и возврата; Escape закрывает активный диалог, а не все окна. При нескольких экземплярах не дублируй ID и не стирай чужие классы/обработчики.
- Предоставь классы или рендеры отдельных окон и понятный способ подключения игровых событий. По умолчанию компоненты получают состояние и отправляют намерения через callbacks; балансом, временем, покупками и сохранением владеет игра. Не выводи игровые правила из одной картинки. Иллюстративное состояние допустимо в отдельном демо; если callback вызывается после его изменения, скажи об этом явно.
- Для монтируемого UI предусмотрены обновление и cleanup; проверяй повторный монтаж, а возврат через Back — если такая навигация создана. Документация соответствует реально экспортируемому API.

## 5. Проверить глазами и действиями

Проверка состоит из двух независимых частей: интерфейс должен **выглядеть похоже** и **действительно работать**. Успешные DOM-тесты не доказывают визуальное сходство.

Используй [verification-and-delivery.md](references/verification-and-delivery.md) для конкретных проверок, снимков, интеграционного примера и упаковки. Сначала сравни при размере исходного изображения; затем проверь узкий экран и контейнер, длинные подписи, переносы и состояния. После смены сцены дождись загрузки изображений и шрифтов перед снимком.

Исправляй сначала крупные различия: геометрия окон → шрифт → подложки/кнопки → иконки → мелкий декор. Не заявляй пиксельное совпадение без соответствующего сравнения; отсутствующий шрифт или неполный источник объясни конкретно.

## 6. Передать готовый результат

- Открой созданное локальное превью либо покажи компоненты средствами существующего проекта. Дай соответствующую ссылку/путь, способ проверки и краткую инструкцию интеграции.
- Если передаёшь ZIP, проверь сам собранный архив: комплектность, запуск после распаковки, отсутствие ненужных файлов и персональных путей. Для первичной проверки есть [audit_bundle.py](scripts/audit_bundle.py); ограничения и разбор результатов описаны в инструкции по выдаче.
- Храни происхождение ассетов и промпты переносимо: относительное имя референса, область crop, тип обработки. Не записывай в экспорт домашний каталог пользователя, путь к кэшу генерации или идентификатор задачи.
- Сохраняй лицензии шрифтов и сведения о происхождении AI-графики. Открытая атрибуция автора и C2PA не равны личным данным пользователя.
- Кратко сообщи, какие экраны и действия готовы, что проверено, где библиотека и как её подключить. Для сгенерированной графики укажи пути и файл промптов согласно `imagegen`.
